# Test cases: the seven rooms

**Source of truth:** [docs/game-design.md](../docs/game-design.md), one section per room.
**Automation:** `tests/ui/rooms.spec.ts`. Each room is solved the way a player would: DOM, console, network, cookies, keyboard.
**Executed:** 2026-11-26, Chromium (Playwright). Status reflects that run.

> Each room's bug is **deliberate**. These test cases check that the bug is present and works as designed, so the puzzle can be solved. A "Pass" means the intended bug behaves as specified.

## Requirement gaps
- **Room 4:** the design doesn't say what happens if the player sets `sr_role` to something other than `user`/`admin`. Observed: anything but exactly `admin` (case-sensitive) is 403. Covered at API level (TC-API-031).
- **Room 5:** the design gives one refund reference for "over 100"; it doesn't say whether larger discounts should change it. Observed: same reference for any value over 100 (TC-API-040).
- **Room 7:** the evidence check is a keyword match, so a report could pass by listing keywords without describing the bug. Accepted for a game; noted in the design doc.
