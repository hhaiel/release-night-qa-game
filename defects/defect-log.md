# Defect Log

> Real bugs in **the game itself**, found while building and testing it. The seven deliberate room bugs are not defects; they're the puzzles (see [docs/game-design.md](../docs/game-design.md)).
> One row per defect, same format as the OrangeHRM project. Continue numbering from the last row.

**Summary:** 9 defects (0 Critical, 0 High, 5 Medium, 4 Low) · 7 fixed and retested, 2 open (1 needs confirmation)
**How they were found:** 4 by manual play-testing while building rooms, 4 by the automated suite on its first run (3 axe, 1 walkthrough), 1 by design review.

## Observations (not defects)
- **Test suite timing:** under parallel load, axe scans took 30+ seconds and some tests timed out. Tests now run with reduced motion (the game supports it), and a11y tests have a 60 s limit. Full suite: 76 tests in about 1.2 minutes, stable over 4 runs.
- **Room 7 evidence check is keyword-based:** a report could pass by listing keywords without describing the bug. Fine for a game.
- **No rate limit on `/api/check`:** codes could be brute-forced, but they're discoverable by playing anyway.
